
[Heading1] Attendance Tracker: Requirements
Oct 28, 2026

[Heading2] Overview
Attendance Tracker is a study app for college students. You add your timetable once (upload a file, or type your lectures in by hand), and the app remembers it for the whole week, every week. Each day it shows your classes, you tap Present or Absent, and it calculates your attendance for every subject and overall, tells you how many classes you can still miss, plans every coming month subject by subject (how many classes, how many to attend, how many you can skip), and warns you before you fall below the percentage you want to keep. It also has a calendar where you can open any past or upcoming day, a box where you paste a deadline message and the app adds it to the calendar and reminds you a week early, and a study progress section for lectures, units, marks and revision.
The app is built by one person working alone, with no deadline and no team split. The study features come from an existing study app, called the "reference app" in this document. Every one of those features is described in full in section E, so no link, repository or outside file is needed. The reference app's gym, food, daily goals and body progress parts are not included.
How to read this document (for a chatbot or developer): it is the single source of truth for what to build. Every requirement has an ID and a priority. Must is the first working version, Should makes it complete, Stretch is only if time allows. Where a decision is marked as a default, build it that way unless the owner says otherwise. Section "Open questions" lists what is still undecided; ask the owner rather than guessing.

[Heading2] User journeys
First launch. Welcome screen → upload timetable (or type it in) → review screen → choose the minimum attendance (default 75%) → enter the semester start date and a tentative end date → the Today screen shows today's classes.
Every day. Open Today → tap Present, Absent or No class on each class → see the subject's percentage and "you can miss N more classes" update at once.
Looking at another day. Open Calendar → tap any date → see that day's classes, their attendance marks and the deadlines on it → edit a mark if needed.
Planning the month. From the first month after the timetable is uploaded, open Today or a subject → see, for each subject, how many classes there are this month, how many to attend and how many can be skipped → skip a class and watch "can skip" drop at once → on a subject page, move to later months until the semester end date, or back to finished months.
A deadline arrives in a chat. Copy the message, e.g. "Maths submission of integration worksheet on 9 Nov" → paste it in the box → review screen shows subject, task, date → confirm → it appears on the calendar and the app reminds you a week before, then closer to the date.
Studying. Open a subject → tick units as revised, add marks → the app shows what to revise before the next test.
Adding the syllabus. Upload the syllabus PDF → a review screen shows each subject's units, topics and course links → confirm → every unit now lists all its topics, and the Special courses part lists every course link, each one opening in a single tap.

[Heading4] E1. Courses screen and subject structure
Each subject card shows its short name (e.g. SDC), full name, credits, a line such as "3 of 5 units revised, 62% of marks so far", the next undone deadline ("Next: Mid-sem, 29 Oct, in 2 days") and a progress bar of units revised. Tapping the card opens it.
An opened subject has up to four parts as chips: Units (called Stages for a project subject), Tasks (only if the subject has task lists), Marks and Due (with a count). Units opens first.
A subject's study structure is: units (title, the topics it covers, hours taught in class), optional task lists, and a marking scheme. A project-type subject has stages instead of units; stages are ticked "done", units are ticked "revised".
A subject with no syllabus yet shows only its deadlines and a prompt to add units (E2).
Subjects are the same ones created from the timetable (A6) and listed under attendance; a subject is added or renamed in one place.

[Heading4] E2. Syllabus to units
Goal: after one upload, every subject shows all its units and, inside each unit, every topic name from the syllabus, in the syllabus order. The user never opens the syllabus file again to see what a unit contains.
Input: the syllabus PDF, which must have selectable text (a scanned or photographed syllabus has no text; the app says so and offers typing it in), or pasted text. One file may hold several subjects; the user ticks which subjects are theirs.
How it is read: by fixed rules S1 to S18 (see "Reading rules"), on the phone, with no AI, no API and no internet. Units, hours and topic names are kept exactly as written.
Review screen: each subject's units and topics are shown beside the original text. The user can edit a topic name, add, delete, reorder, merge or split topics, and move a topic to another unit. Topics that look like several joined together (over 12 words) are flagged orange; anything unclear is flagged and never guessed. Nothing is saved until the user confirms.
Matching: each subject in the syllabus is matched to an existing subject by course code or name; if none matches, a new subject is created.
Every semester: the college uses the same syllabus format each semester, so the same rules apply. A new syllabus keeps ticks for topics with matching names, adds new topics, and asks before removing topics that disappeared.
If a rule fails: the user fixes it on the review screen, and gives the new sample to the developer or chatbot, who updates the rules and the rule log (see "Keeping the rules up to date").
Course links: the Infosys Springboard and other course links in the syllabus are read at the same time (rules L1 to L6) and go to Special courses (section H).
No syllabus file: units and topics can be typed in by hand.

[Heading4] E3. Marking a unit revised
Each unit is a row with a tick circle, "Unit 2: Probability", and small text such as "6 h in class, revised 12 Oct". Tapping the circle stamps today's date and shows a message with Undo for a few seconds; tapping it again removes the tick.
Tapping the row (not the circle) expands it to show the topics it covers, key points, and practice questions if any.
Refresh: a unit already revised can be marked refreshed, which updates its date. This is offered when a test is close (E8).
Topics inside a unit: an opened unit lists every topic from the syllabus (E2), each with its own tick circle. Ticking a topic marks it revised with today's date, with the same Undo message. The unit line reads "7 of 12 topics revised".
Ticking all topics of a unit marks the unit revised automatically. Ticking the unit's own circle ticks all its topics at once. Unticking any topic removes the unit's revised mark.
A subject card also shows "topics revised: N of M" next to its units count, and the exam countdown and revise-next suggestion (E7, E8) name the topics still left in a unit.

[Heading4] E4. Lecture log
This is an addition to the reference app, requested for this app: progress in lectures. Under each subject, the full topic list from the uploaded syllabus (E2), with no retyping. After a lecture the user ticks what was taught, with the date, or types a one-line note on the class slot of that day ("covered Bayes theorem").
Each subject shows "topics covered: N of M" so the user can see what is left before a test, and can link a topic to a unit.

[Heading4] E5. Marks
A subject has a marking scheme: a list of components. Each component has a weight (marks it is worth), a label, the maximum for one entry ("out of"), how many entries are expected, and optionally "best N count". Example: "Online MCQ tests: worth 12, 5 tests, each out of 10"; "Aptitude tests, best 3 of 4: worth 9, each out of 20"; "Mid-semester exam: worth 9, out of 25"; "Attendance: worth 10, taken from attendance"; "Weekly tutorials: worth 20, 15 entries out of 10"; "End-semester exam: worth 40, out of 50". The user builds the scheme by hand.
For each component the user can add a score (marks got, out of), see the scores as small chips, and delete one with a small ×.
A component's result is a fraction: the sum of marks got ÷ the sum of marks out of. If "best N" is set, only the N best scores (by percentage) count. The component contributes weight × fraction.
The attendance component is automatic: its fraction is classes attended ÷ classes held for that subject, and it cannot be edited by hand.
Subject marks so far = the sum of contributions ÷ the sum of weights of the components that have scores, shown as a percentage and as "about X of Y marks". This only shows once at least one non-attendance score has been entered.
Grade guide from that percentage: 90 or more = O, 80 = A+, 70 = A, 60 = B+, 50 = B, 45 = C, 40 = P, below 40 = F. It is labelled "a rough guide", not the real grade.

[Heading4] E6. Deadlines linked to units
A deadline has: title, subject, start date, end date (the same day for a one-day test, or a range for a poster or project), a "tentative" flag, the units it covers, and done yes/no. This extends section D.
It is described in words as "29 Oct, in 2 days", "17–24 Oct, starts tomorrow", "open now", "last day today" or "date passed", with "(tentative)" when flagged.
Units covered can be picked with unit chips (Unit 1, Unit 2, …). If none are picked, the app reads them from the title: "unit 3", "units 1 and 2", "units 2 to 4" and a subject short name in capitals are recognised.
Tick a deadline done to remove it from the active list; it can also be deleted.
Coming up (on Today): the next 3 weeks of deadlines that are not done, nearest first, each with a tick.

[Heading4] E7. Exam countdown (revision plan)
When a deadline that covers units starts within 14 days, Today shows a plan for each day from today to the test: "Test name in N days" followed by a list of days (up to 7 shown).
How the plan is built: take the tests in date order. Each test gets the days from today (or from the day after the previous test) up to the test day. Spread the test's unrevised units evenly over those days ("Revise Unit 3: title"). A unit revised today counts as already planned for today. Days with no revision get "Practise Unit N questions". The last day before the test (if there are 2 or more days) is "Last check": redo the questions missed, or a few questions on the units if none were missed. The test itself is shown on its day.
Items show as done when the unit has been revised or practised that day.

[Heading4] E8. What to revise next
Today shows one suggested unit, with its subject, the unit title and topics, a reason, and two buttons: Practise questions and Mark as revised.
Choice order: look at upcoming tests within 14 days, nearest first. For the first test: an unrevised unit it covers; else a unit with practice questions missed ("Redo questions on…"); else, if the test is at most 4 days away, a unit revised 7 or more days ago ("Refresh…").
With no test close: the first unrevised unit, preferring subjects that have a class on today's timetable, then the subject least revised so far, then the one with more credits.
The reason line says why, e.g. "Revise this for: Mid-sem, 29 Oct, in 2 days." or "SDC is on today's timetable, so go over it while it's fresh."
When every unit is revised, show "Every unit revised. Try a past paper, or give this time to your project." With no units at all: "Go over today's classes. Read your notes from today and try one problem from each class."

[Heading4] E9. Focus timer, weekly chart, streak, stats
Timer: choose Study or Project, and a length of 25 or 50 minutes. Buttons: Start, Pause, Resume, End and log. The timer keeps its end time, so it stays correct if the app is closed and reopened.
When it finishes: a chime and a message "Nice work. 25 minutes logged", then a break button (5 minutes after a 25-minute session, 10 after 50) or Start another session. A break can be skipped. Ending early logs the minutes done; a session under 1 minute is not logged.
Weekly chart: minutes focused on each of the last 7 days as bars, with project minutes shaded differently.
Streak: the number of days in a row with any study activity: a focus session, a unit ticked, a topic ticked, or a practice question answered. If today has no activity yet it still counts back from yesterday and says "Study today to keep it going."
Stats panel at the top of Today: the streak, then bars for units revised (X of Y), practice questions answered right (X of Y) and overall attendance, which is red when below the threshold.

[Heading4] E10. Practice questions with spaced repetition
Each unit can hold practice questions. A question has text, optionally a code snippet or a small data table, and an answer written as a few lines. Questions are added by hand.
A session takes up to 10 questions: first the ones missed before, then reviews that are due (least known first), then new questions in order. If nothing is due, the least-known ones.
For each: show the question ("work it out on paper first"), tap Show answer, then tap Got it or Missed it.
Each question sits in a box from 0 to 4. Right: move up one box (maximum 4). Missed: back to box 0. A question in box 0 is due next session, box 1 after 1 day, box 2 after 3 days, box 3 after 7 days, box 4 after 14 days.
A question missed in a session comes round once more at the end of that session.
At the end: "N of M right first time", the missed ones come back first next time, and a button to practise more if more are due. The unit button reads "Practise questions (N to redo)".

[Heading4] E11. CGPA planner
The user adds semesters. Each semester is entered either By subject (optional name, credits, grade) or I know my SGPA (SGPA and credits).
Grade points: O = 10, A+ = 9, A = 8, B+ = 7, B = 6, C = 5, P = 4, F = 0.
SGPA of a semester = sum of (credits × grade points) ÷ sum of credits. CGPA = sum of (SGPA × credits) ÷ sum of credits over all semesters, shown large at the top with "Across N semesters and C credits".
For subjects with no grade yet, estimate the grade from the marks so far (E5, using the grade guide) and show "on track for an SGPA of about X. A rough guide until results are out."
Planner: the user enters a target CGPA and next semester's credits. Needed SGPA = (target × (credits so far + next credits) − points so far) ÷ next credits, rounded up to 2 decimals. If it is above 10: "Not reachable in one semester. Even a perfect 10 takes you to X." If it is 0 or less: "You're already safe. Any SGPA keeps you at X or above."
Semesters can be added and deleted; numbers update as the user types.

[Heading4] E12. AI tutor
Opened from a unit ("Explain it to me"), from a practice question ("Ask the tutor to walk me through it") or from a roadmap topic. It is a sheet that slides up with the subject and unit as its title, a few quick-question chips, a text box and an Ask button that becomes Stop while the answer streams in.
One conversation is kept per unit or topic; the last 12 messages are sent each time, with the unit's title, topics and key points as hidden context.
The AI is told: answer in simple English and short paragraphs; define a technical term the first time; use one everyday example or analogy; stay under about 250 words unless asked; for a practice problem give exactly one problem and stop, with hints or the full solution only when asked; format with Markdown (bullets, bold key terms, code blocks, no tables); stay inside what the syllabus covers at first-year university level; give short runnable Python with expected output when code helps.
Needs the internet and an AI service. This is the one study feature that cannot be rule-based, so it can be left out completely; if it is left out, nothing else depends on it.

[Heading4] E13. Self-study roadmap
An optional personal learning path next to college. It is made of phases (for example "Python from zero", "Developer toolkit"), each with a name and a one-line reason, and each holding topics.
A topic has a title, a short description, an estimated number of hours and links to free resources. The user can add their own phases and topics, or paste a list, which is split into topics by the same rules as the syllabus (S10 to S16).
Tick a topic done with the date. A phase shows "N of M done, about X h left" and a progress bar; a finished phase is marked Complete. The whole roadmap shows "N of T topics done. About H hours to go, roughly M months at an hour a day". The next undone topic is highlighted.
Topics can be tagged to a personal project, and the roadmap filtered to "Skills for your project" in learning order.

[Heading4] E14. Start a new semester
A button in the Subjects screen (two taps to confirm) clears the timetable, attendance, marks, scores and deadlines for the old term and starts the setup of the new one. CGPA data and focus history are kept.

[Heading4] E15. Week ahead and task lists
On Sundays, Today shows "The week ahead": Monday to Saturday, each day with the number of classes and the time from the first start to the last end, the subjects, and any deadline starting that day, plus "Revise before this week's tests: SDC unit 3, …".
Task lists: a subject can have a checklist (for example weekly tutorial questions or online course modules). A list tied to a class type shows its next undone item on the day of that class ("SDC tutorial on Thursday"); a list tied to a deadline shows its next undone item within 3 weeks of it ("2 modules left, 30 Oct"). They appear under "To do" on Today and can be ticked.

[Heading4] E16. Next class and leave-by time
When today's classes are over, Today shows the next class day: "Tomorrow: SDC Lecture at 9:00 in room B-204. Leave by 8:25." Leave-by time = first in-person class start minus the user's commute minutes minus 5, rounded down to 5 minutes. Online classes get no leave-by time. The commute is a setting (default 30 minutes).
Not included from the reference app: gym workouts and cardio, food and calories, daily goals and habits, weight, waist and lift records, the in-app Suggest tab, and the pre-filled timetable, subjects and test dates of one specific college batch.

[Heading3] J. Monthly attendance plan
From the first month after the timetable is uploaded, the app plans every month for every subject. For each subject it shows how many classes the subject will have that month, how many of them the user must attend to stay at the threshold, and how many can be skipped. The numbers include all earlier attendance: skipping classes shrinks what is left to skip, and unused skips carry over into the following months. The plan is per subject only, because the college counts attendance per subject, and it uses the one threshold from Settings (F1) for every subject.

[Heading4] How the numbers are worked out
Before the month: H = classes held and A = classes attended up to the end of the previous month, from the user's marks, any totals typed in (B8) and the assumed past attendance (J5).
Classes in the month (C): the classes on the weekly timetable in that month, minus holiday days (A12), minus classes marked No class. Exam days are not subtracted: classes on exam days count as normal classes.
Done so far this month: p = classes marked Present, a = classes marked Absent. Classes left, R = C − p − a.
Needed by the end of the month: the smallest whole number of attended classes that keeps the subject at or above the threshold t, which is ceil(t × (H + C) ÷ 100).
Must attend (N): the needed number − (A + p), never below 0. Can skip: R − N.
Out of reach: if N is more than R, even attending every class left is not enough. The plan then shows the percentage the user will end the month on if they attend all R classes: (A + p + R) ÷ (H + C) × 100, to one decimal place.
All of this uses whole numbers, the same way as B4 and B5, so a result never changes between runs.

[Heading4] Typography
Headings and big numbers: a characterful rounded or grotesque font in bold to extra-bold, for example Bricolage Grotesque or Plus Jakarta Sans.
Body text: a clean friendly font such as DM Sans.
Fonts are bundled inside the app (not loaded from the internet), so the app looks the same offline. Provide a system-font fallback.
Sizes: big attendance number 48 to 56 px; screen title 28 px; card title 18 px; body 15 to 16 px; small label 12 to 13 px. Section titles are small, capital and letter-spaced, like "RECOMMENDED WITH DEALS" in the Zomato screenshot.
Numbers (percentages, dates, countdowns) use fixed-width digits so they do not jump when they change.

[Heading4] Shape, depth and spacing
Corner radius: cards 20 to 24 px; sheets 28 px on top; buttons, chips, search bars and the bottom bar fully round (pill); icon tiles circles.
Shadows are soft and layered (for example 0 8px 24px at 12% of the main colour), never hard black. The floating bottom bar sits on a slightly blurred, semi-transparent background, so content shows faintly behind it, as in the Zomato screenshot.
Gradients are used on the header, the main banner and progress bars, but in two close warm colours, not rainbow.
Spacing follows an 8 px grid: 16 to 20 px screen margins, 12 px between cards. Buttons and tap targets are at least 48 px tall. Leave at least 96 px at the bottom of every scrolling screen so the floating bar never hides content.

[Heading4] Navigation: the floating pill bar
A rounded pill floating 12 to 16 px above the bottom edge and inset from the sides, with a soft shadow and a slight blur.
Four items: Today, Calendar, Subjects, Settings. The active item is a filled pill (the primary colour, or dark in the light theme) showing its icon and its label; the others show a soft icon, with a small label.
The filled pill slides from one item to the next with a springy animation.
Beside the bar, a round floating button with a gradient (as the purple circle in the Zomato screenshot). It opens quick add: paste a reminder, add a lecture, add a deadline.
The bar slides down out of the way when scrolling down and returns when scrolling up. It respects the phone's bottom safe area.

[Heading2] Reading rules (no AI)
The timetable, reminder messages, the syllabus and the course links are read by fixed rules that run on the phone. There is no AI and no API in these four parts, and they work offline. The rules below were built and tested on the real Semester 1 files: a 43-page syllabus PDF with 7 subjects and 30 units, and one real college message. Every result goes to a review screen before anything is saved.

[Heading4] Keeping the rules up to date
The college uses the same syllabus format every semester, so these rules are the starting set, not a finished list. Whenever the owner gives a new sample syllabus, or a new kind of college message, the chatbot or developer building the app must:
Run the readers on the new sample and compare the result with the file: every unit, its hours, its topics and every course link.
Where something comes out wrong, add a new rule or change an existing one, and write it in the rule log below with the date and the example that needed it.
Run all the earlier samples again to check that nothing that worked before has broken. Rules are numbered and are never removed without being logged.
Keep the readers as one small module with automatic tests built from the sample files and the acceptance results below.
The owner will provide a sample syllabus each semester. If one has not been provided, ask for it before building or changing the syllabus reader.

"Server-" + "Side"; "self-" + "regulation"

ASEP's 15 guidelines

[Heading2] AI use
No core feature uses AI or an API. The timetable, reminder messages, the syllabus and the course links are read by the fixed rules in "Reading rules (no AI)", and all numbers (attendance, days left) are calculated on the phone. The only optional feature that needs an AI service is the tutor chat (E12), which can be left out completely.

[Heading2] Architecture and tech stack
The phone does almost everything: it stores the data, calculates attendance, draws the calendar and schedules the notifications. No server is needed for the core app.

[Heading2] Safety, privacy and quality
Accuracy
The user confirms every reading (timetable, deadline, syllabus, course links) on a review screen. Nothing is saved on its own.
Unclear text is flagged, not guessed. The review screen shows the original photo or message next to the fields.
Attendance maths is plain code with fixed formulas (B2, B4, B5), so results are always the same and work offline.
The app shows its own figures; the college ERP is the official record. The app says so once, and lets the user correct totals (B8).
Privacy
Timetable, attendance, deadlines and marks stay on the device. Nothing is sent to any server.
No account and no sign-in.
The timetable, reminders, the syllabus and course links are read on the phone and never leave it.
